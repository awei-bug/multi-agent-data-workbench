# 企业级推进说明

## 已落地的第一阶段能力

当前项目已经从“单机单用户演示态”推进到“具备多用户/多租户隔离基础”的阶段，核心变化如下：

1. 后端请求作用域

- 每个请求现在都会识别 `x-workspace-tenant-id` 和 `x-workspace-user-id`
- 如果前端暂时不传，也会自动回落到默认值，保证现有页面不需要改动即可继续使用
- 响应头会回写当前生效的租户和用户，便于后续前端接入登录态

2. 工作台会话隔离

- 活动任务 `active_task`
- 工作台元数据 `meta`
- 已上传数据集 `uploaded_files`
- 运行产物 `artifacts`

以上内容已经按 `tenant + user` 维度隔离，不同用户不会再共用同一份当前会话数据。

3. 历史任务与模板隔离

- 历史任务现在按租户和用户分别存储
- 工作台保存的模板也按租户和用户分别存储
- 系统模板保留为租户级共享能力，避免每个用户重复初始化

4. 审计日志隔离

- 审计事件已经记录 `tenantId` 和 `ownerId`
- 查询审计日志时只返回当前作用域下的数据

## 当前兼容方式

前端如果什么都不传，系统默认使用：

- `WORKSPACE_DEFAULT_TENANT_ID=local-tenant`
- `WORKSPACE_DEFAULT_USER_ID=local-user`

因此当前 MVP 交互不会被破坏。

如果后续接入登录系统，只需要在前端请求头里补充：

```text
x-workspace-tenant-id: 你的租户ID
x-workspace-user-id: 当前用户ID
```

即可切换到真实多用户隔离模式。

## 这一阶段的价值

这一步的意义不是做一个“登录页面”，而是先把真正的后端数据边界建起来。只有把数据隔离、模板隔离、审计隔离做好，后续再接：

- 统一登录
- RBAC 权限控制
- 组织级工作空间
- 异步任务队列
- 企业级审计追踪

才不会推倒重来。

## 本阶段新增：本地账号 + JWT + RBAC

已落地：

1. `users` 表与注册/登录接口
2. JWT access token（Bearer）
3. 中间件优先从 JWT 解析 `tenantId` / `userId`，忽略可伪造请求头
4. 前端登录页、token 存储、请求自动携带 Authorization
5. 生产可通过 `WORKSPACE_AUTH_REQUIRED=true` 强制鉴权
6. RBAC 角色：`viewer` / `analyst` / `admin`
7. 写操作权限校验与管理接口角色保护
8. 首个注册用户自动成为 admin，后续用户默认 analyst
9. 管理员可在设置页调整同租户用户角色
10. 工作流异步执行：提交后后台推进节点，前端轮询状态
11. 任务执行元数据：`execution.status` / `jobId` / `steps`
12. `GET /api/workflow/jobs/current` 查询当前作用域作业
13. 关系化 scope 列：`history_tasks` / `templates` / `audit_events` 增加 `tenant_id` / `owner_id`
14. 查询改为按 scope 列过滤，并增加复合索引
15. 结构化 JSON 日志（可选）与 Prometheus `/metrics`
16. 请求量、延迟直方图、工作流作业、鉴权失败、限流指标
17. Redis 共享工作流队列 + 独立 worker（`WORKSPACE_QUEUE_BACKEND=redis`）
18. Compose 增加 redis 与 worker 服务，支持多实例消费
19. Sentry 错误追踪与 Webhook 告警联动
20. 管理接口可查询最近错误事件
21. CD 流水线：构建并推送 backend/frontend 镜像到 GHCR
22. 发布清单：`docker-compose.release.yml` + `tools/release.ps1` / `tools/release.sh`
23. Staging 远程自动部署：SSH + compose + 健康检查
24. 多实例共享限流：`WORKSPACE_RATE_LIMIT_BACKEND=redis`
25. 外部连接器：HTTP JSON / PostgreSQL + 凭据加密存储
26. Production 审批部署：GitHub Environment + v* 标签门禁

权限摘要：

- `viewer`：只读
- `analyst`：读写（分析主流程）
- `admin`：读写 + 删除/审计/角色管理

环境变量：

- `WORKSPACE_AUTH_SECRET`
- `WORKSPACE_AUTH_TOKEN_MINUTES`
- `WORKSPACE_AUTH_REQUIRED`
