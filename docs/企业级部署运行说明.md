# 企业级部署运行说明

## 1. 文档目标

本文档说明当前多 Agent 协同数据分析创作工作台在本地、测试环境和准生产环境下的运行方式、关键环境变量、健康探针和管理接口保护方式。

## 2. 项目结构

- `frontend/`
  - React + Vite 前端工作台
- `backend/`
  - FastAPI 后端服务
  - PostgreSQL / SQLite 数据存储
  - 文件上传、分析流程、报告导出、审计事件

## 3. 后端启动入口

- `backend/start-workspace-api.py`

## 4. 后端关键环境变量

- `WORKSPACE_API_HOST`
  - 默认：`127.0.0.1`
- `WORKSPACE_API_PORT`
  - 默认：`8787`
- `WORKSPACE_DATABASE_URL`
  - 生产建议使用 PostgreSQL
- `WORKSPACE_MODEL_BASE_URL`
  - 默认：`https://apihub.agnes-ai.com/v1`
- `WORKSPACE_MODEL_NAME`
  - 默认：`Agnes 2.0 Flash`
- `AGNES_API_KEY` / `OPENAI_API_KEY` / `APIHUB_API_KEY`
  - 任一可用即可
- `WORKSPACE_ADMIN_API_KEY`
  - 管理接口口令
  - 未设置时，不启用管理接口保护
- `WORKSPACE_AUTH_SECRET`
  - JWT 签名密钥
  - 生产环境必须改为足够长的随机串
- `WORKSPACE_AUTH_TOKEN_MINUTES`
  - 默认：`720`
- `WORKSPACE_AUTH_REQUIRED`
  - 默认：`false`
  - 设为 `true` 后，除健康检查与登录/注册外都必须带 Bearer token
- `WORKSPACE_WORKFLOW_ASYNC`
  - 默认：`true`
  - 工作流是否异步后台执行
- `WORKSPACE_WORKFLOW_STEP_DELAY_MS`
  - 默认：`0`
  - 异步推进每个节点之间的延迟（毫秒），便于观察进度
- `WORKSPACE_JSON_LOGS`
  - 默认：`false`
  - 设为 `true` 后输出 JSON 结构化日志
- `WORKSPACE_METRICS_ENABLED`
  - 默认：`true`
  - 是否暴露 `/metrics` 与 `/api/metrics`
- `WORKSPACE_QUEUE_BACKEND`
  - 默认：`memory`
  - 可选：`memory` / `redis`
- `WORKSPACE_REDIS_URL`
  - Redis 连接串，例如 `redis://127.0.0.1:6379/0`
  - `WORKSPACE_QUEUE_BACKEND=redis` 时必填
- `WORKSPACE_ERROR_TRACKING_ENABLED`
  - 默认：`true`
- `WORKSPACE_SENTRY_DSN`
  - Sentry DSN；为空时仅本地缓冲错误
- `WORKSPACE_SENTRY_ENVIRONMENT`
  - 默认：`local`
- `WORKSPACE_SENTRY_TRACES_SAMPLE_RATE`
  - 默认：`0`
- `WORKSPACE_ALERT_WEBHOOK_URL`
  - 可选告警 Webhook（钉钉/企微/Slack 兼容 JSON）
- `WORKSPACE_ALERT_MIN_LEVEL`
  - 默认：`error`
  - 可选：`warning` / `error` / `fatal`
- `WORKSPACE_RATE_LIMIT_BACKEND`
  - 默认：跟随 `WORKSPACE_QUEUE_BACKEND`，否则 `memory`
  - 可选：`memory` / `redis`
  - 多实例部署建议 `redis`
- `WORKSPACE_RATE_LIMIT_PER_MINUTE`
  - 默认：`120`
- `WORKSPACE_CREDENTIALS_SECRET`
  - 外部连接凭据加密密钥
  - 默认回退到 `WORKSPACE_AUTH_SECRET`
- `WORKSPACE_MODEL_TIMEOUT_SECONDS`
  - 默认：`60`
- `WORKSPACE_LOG_LEVEL`
  - 默认：`INFO`
  - 可选：`DEBUG`、`INFO`、`WARNING`、`ERROR`
- `WORKSPACE_RUN_MIGRATIONS_ON_START`
  - 默认：`true`
  - 启动后端时自动执行 Alembic 迁移
- `WORKSPACE_RATE_LIMIT_PER_MINUTE`
  - 默认：`120`
- `WORKSPACE_MAX_REQUEST_BODY_BYTES`
  - 默认：`10000000`
- `WORKSPACE_CORS_ORIGINS`
  - 多个值使用逗号分隔

## 5. 本地启动方式

### 5.1 启动后端

```powershell
$env:PYTHONPATH="backend"
python backend/start-workspace-api.py
```

默认会在启动前自动执行数据库迁移。

如果端口被占用，可切换端口：

```powershell
$env:WORKSPACE_API_PORT="8788"
$env:PYTHONPATH="backend"
python backend/start-workspace-api.py
```

### 5.2 启动前端

```powershell
cd frontend
npm install
npm run dev
```

如果前端需要显式指定后端地址：

```powershell
$env:VITE_WORKSPACE_API_BASE_URL="http://127.0.0.1:8787"
npm run dev
```

## 7. 错误响应约定

后端统一错误结构：

```json
{
  "error": {
    "code": "http_404",
    "message": "resource not found",
    "details": {}
  },
  "requestId": "..."
}
```

适用范围：

- 业务异常
- 请求体过大
- 速率限制
- 参数校验失败
- 未处理异常

## 9. 管理接口保护

如果设置了 `WORKSPACE_ADMIN_API_KEY`，以下敏感接口需要在请求头中携带管理口令：

```http
x-admin-api-key: 你的管理口令
```

当前已纳入保护的接口包括：

- `GET /api/audit/events`
- `POST /api/templates/save-active-task`
- `DELETE /api/history/tasks/{task_id}`
- `DELETE /api/datasets/{dataset_id}`
- `DELETE /api/tasks/active/report`

## 10. 生产部署建议

当前版本适合继续向以下方向推进：

- 使用 PostgreSQL 作为正式数据库
- 通过 Nginx 或网关统一反向代理
- 用进程管理器托管后端服务
- 将日志输出接入集中日志平台
- 为上传目录、导出目录配置独立持久化存储
- 在多实例部署时将当前单进程限流替换为网关或 Redis 方案

## 12. 本地账号鉴权与 RBAC

接口：

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/auth/users`（admin）
- `PATCH /api/auth/users/{user_id}/role`（admin）

登录成功后返回：

```json
{
  "accessToken": "...",
  "tokenType": "Bearer",
  "expiresInMinutes": 720,
  "user": {
    "id": "user-...",
    "username": "analyst_a",
    "tenantId": "tenant-a",
    "displayName": "Analyst A",
    "role": "analyst",
    "permissions": ["read", "write"]
  }
}
```

角色：

- `viewer`：只读
- `analyst`：读写
- `admin`：读写 + 管理

后续请求携带：

```http
Authorization: Bearer <accessToken>
```

后端会用 JWT 中的 `tenantId` / `sub` / `role` 绑定工作空间作用域与权限。
写操作（POST/PUT/PATCH/DELETE）对 `viewer` 返回 403。
管理接口接受：

1. `x-admin-api-key`（若已配置）
2. 或 JWT 中的 `admin` 角色

## 13. 异步工作流

默认 `WORKSPACE_WORKFLOW_ASYNC=true`：

1. `POST /api/workflow/action` 立即返回 `running` 状态
2. 后台线程逐步 `advance` 节点
3. 前端轮询 `GET /api/tasks/active` 或 `GET /api/workflow/jobs/current`
4. 作业状态：`queued → running → succeeded/failed/cancelled`

任务响应中的 `execution` 字段示例：

```json
{
  "mode": "async",
  "status": "running",
  "jobId": "job-abc123",
  "steps": 2,
  "submittedAt": "...",
  "startedAt": "..."
}
```

## 14. 数据关系化进度

当前迁移链：

1. `0001_initial_schema`：基础 JSON 表
2. `0002_users`：用户认证表
3. `0003_scope_columns`：历史任务/模板/审计增加 scope 列与索引

`history_tasks` / `templates` / `audit_events` 现已具备：

- `tenant_id`
- `owner_id`
- 对应复合索引

查询隔离从“全表加载 + JSON 过滤”升级为“scope 列条件过滤”。
payload 仍保留完整业务内容，便于兼容既有前端结构。

## 15. 可观测性

### 15.1 结构化日志

设置：

```env
WORKSPACE_JSON_LOGS=true
```

后，日志按行输出 JSON，包含：

- `request_id`
- `tenant_id` / `user_id`
- `method` / `path` / `status`
- `duration_ms`

便于接入 Loki / ELK / CloudWatch。

### 15.2 Metrics

接口：

- `GET /metrics`：Prometheus 文本格式
- `GET /api/metrics`：JSON 快照

关键指标：

- `workspace_http_requests_total`
- `workspace_http_request_duration_ms`（histogram）
- `workspace_http_request_errors_total`
- `workspace_workflow_jobs_total`
- `workspace_workflow_job_steps_total`
- `workspace_auth_failures_total`
- `workspace_rate_limited_total`

`/api/health` 也会返回 `observability.snapshot` 摘要。

## 16. Redis 共享工作流队列

默认本地仍可用进程内队列：

```env
WORKSPACE_QUEUE_BACKEND=memory
```

多实例 / Compose 生产建议：

```env
WORKSPACE_QUEUE_BACKEND=redis
WORKSPACE_REDIS_URL=redis://redis:6379/0
WORKSPACE_WORKFLOW_ASYNC=true
```

启动 worker：

```powershell
$env:PYTHONPATH="backend"
$env:WORKSPACE_QUEUE_BACKEND="redis"
$env:WORKSPACE_REDIS_URL="redis://127.0.0.1:6379/0"
python backend/start-workflow-worker.py
```

行为：

1. API `POST /api/workflow/action` 仅入队 Redis
2. worker 进程领取任务并逐步 `advance`
3. 前端继续轮询 `/api/tasks/active` 或 `/api/workflow/jobs/current`
4. 作业状态保存在 Redis，多 API 实例可见

Docker Compose 已包含：

- `redis`
- `backend`
- `worker`
- `frontend`
- `postgres`

## 17. 错误追踪与告警

推荐生产配置：

```env
WORKSPACE_ERROR_TRACKING_ENABLED=true
WORKSPACE_SENTRY_DSN=https://<key>@oxxxx.ingest.sentry.io/<project>
WORKSPACE_SENTRY_ENVIRONMENT=production
WORKSPACE_SENTRY_TRACES_SAMPLE_RATE=0.1
WORKSPACE_ALERT_WEBHOOK_URL=https://hooks.example.com/workspace-alerts
WORKSPACE_ALERT_MIN_LEVEL=error
```

能力：

1. 未处理 HTTP 异常自动上报
2. 工作流失败事件自动上报
3. 可选推送到 Webhook 告警通道
4. 管理接口查询最近错误：

```http
GET /api/errors/recent?limit=20
x-admin-api-key: <admin-key>
```

或使用 admin JWT。

`/api/health` 与 `/api/metrics` 会返回 `errorTracking` 摘要：

- `totalCaptured`
- `totalAlerts`
- `sentryEnabled`
- `recent`

## 19. 多实例共享限流

本地默认：

```env
WORKSPACE_RATE_LIMIT_BACKEND=memory
WORKSPACE_RATE_LIMIT_PER_MINUTE=120
```

多实例 / Compose 建议：

```env
WORKSPACE_RATE_LIMIT_BACKEND=redis
WORKSPACE_REDIS_URL=redis://redis:6379/0
WORKSPACE_RATE_LIMIT_PER_MINUTE=120
```

行为：

1. 固定 60 秒窗口计数
2. 优先按登录用户维度限流（`user:<tenant>:<user>`）
3. 未登录回退到 IP 维度
4. 超限返回 `429`，并带：
   - `retry-after`
   - `x-ratelimit-limit`
   - `x-ratelimit-remaining`
   - `x-ratelimit-backend`

`/api/health` 会返回：

```json
{
  "rateLimit": {
    "backend": "redis",
    "perMinute": 120
  }
}
```

## 20. 外部数据源连接器

当前支持：

1. `http_json`：HTTP/HTTPS JSON 接口
2. `postgres`：PostgreSQL SQL 查询（仅 SELECT/WITH）

关键接口：

- `GET /api/connectors/types`
- `GET /api/connections`
- `POST /api/connections`
- `PATCH /api/connections/{id}`
- `DELETE /api/connections/{id}`
- `POST /api/connections/{id}/test`
- `POST /api/connections/{id}/import`

凭据处理：

- 使用 `WORKSPACE_CREDENTIALS_SECRET` 加密后存储
- 列表接口不回传明文凭据
- 导入成功后进入 `/api/datasets`，可绑定到工作流
