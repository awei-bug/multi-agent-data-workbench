# 持续交付说明

## 目标

在现有 CI 校验通过后，自动构建并推送可部署镜像，支持：

1. GitHub Actions CD（推送到 GHCR）
2. 本地 release 脚本（构建/推送/部署）
3. 使用预构建镜像的 Compose 发布清单

## 工作流

### 1) CI（质量门禁）

- 文件：`.github/workflows/ci.yml`
- 触发：`push/PR` 到 `main`、手动触发
- 内容：后端测试、前端测试/构建/E2E、compose 配置校验

### 2) CD（镜像发布）

- 文件：`.github/workflows/cd.yml`
- 触发：
  - 推送 `v*` 标签（例如 `v1.2.0`）
  - 推送到 `main`（生成 `sha-xxxxxxx` 与 `main` 标签）
  - 手动 `workflow_dispatch`
- 产物：
  - `ghcr.io/<owner>/<repo>/backend:<version>`
  - `ghcr.io/<owner>/<repo>/frontend:<version>`
  - worker 复用 backend 镜像
  - `release-manifest` artifact

## 镜像命名

```text
ghcr.io/<owner>/<repo>/backend:<version>
ghcr.io/<owner>/<repo>/frontend:<version>
```

`<version>` 规则：

- 标签发布：`v1.0.0`（并额外打 `latest`）
- main 提交：`sha-<7位sha>`（并额外打 `main`）
- 手动触发：可用 `tag_override` 指定

## 本地发布

### Windows

```powershell
# 仅构建
powershell -ExecutionPolicy Bypass -File tools\release.ps1

# 构建并部署到本机（使用预构建镜像 compose）
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -Deploy

# 构建 + 推送 + 部署
powershell -ExecutionPolicy Bypass -File tools\release.ps1 `
  -ImagePrefix "ghcr.io/<owner>/<repo>" `
  -Tag "v1.0.0" `
  -Push `
  -Deploy
```

### Linux / macOS

```bash
# 仅构建
bash tools/release.sh

# 构建并部署
IMAGE_PREFIX=workbench TAG=v1.0.0 DEPLOY=true bash tools/release.sh

# 构建并推送
IMAGE_PREFIX=ghcr.io/<owner>/<repo> TAG=v1.0.0 PUSH=true bash tools/release.sh
```

## 使用预构建镜像部署

1. 准备环境变量文件（可从 `.env.compose.example` 复制）
2. 设置镜像前缀与标签：

```powershell
$env:IMAGE_PREFIX="ghcr.io/<owner>/<repo>"
$env:IMAGE_TAG="v1.0.0"
docker compose -f docker-compose.release.yml --env-file .env up -d
```

3. 验证：

```powershell
docker compose -f docker-compose.release.yml ps
Invoke-WebRequest http://127.0.0.1:8787/api/health
Invoke-WebRequest http://127.0.0.1:8787/metrics
```

## GHCR 权限说明

CD 使用 `GITHUB_TOKEN` 推送到 GitHub Container Registry。

首次使用建议：

1. 仓库 Settings → Actions → General → Workflow permissions
2. 选择 Read and write permissions
3. 保存后重新触发 CD

私有仓库镜像拉取时，目标机器需登录：

```bash
echo $GHCR_TOKEN | docker login ghcr.io -u <github-username> --password-stdin
```

## 推荐发布流程

1. 合并到 `main`，确认 CI 全绿
2. 打版本标签并推送：

```bash
git tag v1.0.0
git push origin v1.0.0
```

3. 等待 CD 完成，确认 GHCR 出现镜像
4. 在目标环境执行：

```bash
export IMAGE_PREFIX=ghcr.io/<owner>/<repo>
export IMAGE_TAG=v1.0.0
docker compose -f docker-compose.release.yml --env-file .env pull
docker compose -f docker-compose.release.yml --env-file .env up -d
```

5. 跑上线检查清单（健康、登录、工作流、metrics、错误追踪）

## 回滚

```bash
export IMAGE_PREFIX=ghcr.io/<owner>/<repo>
export IMAGE_TAG=v0.9.0   # 上一个稳定版本
docker compose -f docker-compose.release.yml --env-file .env up -d
```

## 远程 Staging / Production 部署

CD 现已支持：

- Staging：自动/手动部署（`environment: staging`）
- Production：版本标签 + 审批后部署（`environment: production`）

详细步骤见：

- [远程部署说明.md](./远程部署说明.md)
- [生产部署说明.md](./生产部署说明.md)

手动远程部署：

```bash
export DEPLOY_HOST=staging.example.com
export DEPLOY_USER=deploy
export DEPLOY_SSH_KEY_PATH=~/.ssh/staging_deploy
export IMAGE_PREFIX=ghcr.io/<owner>/<repo>
export IMAGE_TAG=v1.0.0
bash tools/ssh-deploy.sh
```

## 当前边界

- 已支持：构建推送镜像 + staging 自动部署 + production 审批部署
- 生产审批依赖 GitHub Environment reviewers 配置
- 未内置 K8s/Helm；当前模型是 VM + compose
