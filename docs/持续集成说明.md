# 持续集成说明

## 目标

本项目已接入 GitHub Actions 持续集成，目标是保证前后端主流程、构建产物和容器编排配置在提交后可以自动校验。

## 工作流位置

- `.github/workflows/ci.yml`：持续集成
- `.github/workflows/cd.yml`：持续交付（镜像构建与推送）
- 详细 CD 说明见：[持续交付说明.md](./持续交付说明.md)

## 当前校验范围

### 1. 后端测试

- 安装 `backend/requirements.txt`
- 补充安装 `pytest`
- 运行以下测试集：
  - `backend/tests/test_config.py`
  - `backend/tests/test_migrations.py`
  - `backend/tests/test_workspace_api.py`
  - `backend/tests/test_workflow_service.py`
  - `backend/tests/test_document_analysis_path.py`
  - `backend/tests/test_auth.py`
  - `backend/tests/test_rbac.py`
  - `backend/tests/test_async_workflow.py`
  - `backend/tests/test_relational_scope.py`
  - `backend/tests/test_observability.py`
  - `backend/tests/test_redis_queue.py`
  - `backend/tests/test_error_tracking.py`
  - `backend/tests/test_rate_limit.py`
  - `backend/tests/test_connectors.py`

### 2. 前端测试与构建

- 在 `frontend/` 目录执行 `npm ci`
- 安装 Playwright Chromium 浏览器
- 运行 `npm test -- --reporter=dot`
- 运行 `npm run build`
- 运行 `npm run test:e2e`

### 3. Compose 配置校验

- 执行 `docker compose config`
- 用于提前发现 `docker-compose.yml` 中的变量、依赖关系和语法问题

## 触发方式

- 推送到 `main`
- 向 `main` 发起 Pull Request
- 手动触发 `workflow_dispatch`

## 本地对齐验证命令

在提交前，建议先在本地执行与 CI 对齐的命令：

```powershell
$env:PYTHONPATH='backend'
python -m pytest backend/tests/test_config.py backend/tests/test_migrations.py backend/tests/test_workspace_api.py backend/tests/test_workflow_service.py backend/tests/test_document_analysis_path.py backend/tests/test_auth.py backend/tests/test_rbac.py backend/tests/test_async_workflow.py backend/tests/test_relational_scope.py backend/tests/test_observability.py backend/tests/test_redis_queue.py backend/tests/test_error_tracking.py backend/tests/test_rate_limit.py backend/tests/test_connectors.py

cd frontend
npm test -- --reporter=dot
npm run build
cd ..

docker compose config
```

## 与 CD 的关系

1. CI 负责质量门禁（测试/构建/compose 校验）
2. CD 负责产物发布（Docker 镜像推送到 GHCR）
3. 生产部署使用 `docker-compose.release.yml` 拉取预构建镜像

本地快速发布：

```powershell
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -Deploy
```

## 说明

- 后端测试使用 `PYTHONPATH=backend`，避免在 CI 和本地出现 `ModuleNotFoundError: backend_py`。
- 前端 E2E 依赖 Playwright 浏览器安装步骤，不能省略。
- 如果后续增加新的核心页面、接口或部署脚本，应同步把对应校验加入 `ci.yml`。
