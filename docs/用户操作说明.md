# 用户操作说明

## 文档目的

这份文档面向第一次接触项目的使用者，说明当前系统应该怎么正常操作，以及每个主要页面的作用。

## 启动项目

在项目根目录执行：

```powershell
Copy-Item .env.example .env
powershell -ExecutionPolicy Bypass -File tools\start-workspace.ps1
```

启动后访问：

- 总览页：`http://127.0.0.1:5174/dashboard`
- 数据源页：`http://127.0.0.1:5174/data-sources`
- 输入准备页：`http://127.0.0.1:5174/workspace/input`
- 执行监控页：`http://127.0.0.1:5174/workspace/execution`
- 报告交付页：`http://127.0.0.1:5174/workspace/output`

如果只想确认服务是否正常，可检查：

- 前端首页是否能打开
- 后端健康接口：`http://127.0.0.1:8787/api/health`

## 正常使用流程

### 1. 进入数据源页面

路径：`/data-sources`

作用：

- 上传新的数据文件
- 查看已经上传过的数据源
- 把某个数据源绑定到当前分析任务

当前支持的文件类型：

- CSV
- Excel
- JSON
- TXT
- Markdown
- Word
- PDF

注意：

- 前端限制单文件不超过 `7MB`
- 上传成功后，数据源会出现在“已上传数据源”列表中

### 2. 绑定数据源

在“已上传数据源”卡片上点击 `用于新分析`。

成功后，系统会提示：

- 已绑定某个文件
- 当前任务状态会变成 `等待需求解析`

这一步很重要。没有绑定数据源时，后续需求解析和分析流程都不会正常进入。

### 3. 进入输入准备

路径：`/workspace/input`

作用：

- 查看当前已经绑定的数据源
- 输入自然语言分析需求
- 让系统把需求解析成结构化分析意图

示例输入：

- `分析各产品容量与循环寿命的关系，并给出结论`
- `按型号比较额定容量、效率和寿命，输出图表和摘要`

点击解析后，系统会：

- 调用后端意图解析接口
- 生成分析目标、指标、维度等结构化结果
- 把当前任务更新到可执行状态

### 4. 进入执行监控

路径：`/workspace/execution`

作用：

- 启动工作流
- 查看七个 Agent 节点的执行状态
- 查看中间数据和图表
- 必要时进行人工修正

当前执行链路包括：

1. 数据接入 Agent
2. 数据清洗 Agent
3. 指标计算 Agent
4. 可视化 Agent
5. 洞察分析 Agent
6. 报告生成 Agent
7. 审核校验 Agent

在这个页面里，你可以：

- 点击启动工作流
- 查看节点状态变化
- 查看图表区
- 对数据进行人工修正后重新执行

### 5. 查看图表

图表在执行监控页内展示。

当前图表不是默认全铺开，而是先让你选择类型，再显示对应图表。

当前可选图表：

- 排名柱状图
- 占比环图
- 趋势折线图
- 散点图
- 多指标雷达图

说明：

- 如果某些图表不可选，通常是因为当前数据里可识别的数值字段不够
- 系统已经支持识别一部分带单位和符号的业务值，例如 `%`、`+`、`P`

### 6. 进入报告交付

路径：`/workspace/output`

作用：

- 编辑报告摘要
- 导出最终文件
- 保存为模板

当前支持导出：

- Markdown
- HTML
- Word
- PDF

注意：

- 只有工作流跑到审核完成后，导出才算完整

## 其他页面作用

### 总览

路径：`/dashboard`

作用：

- 查看当前任务状态
- 查看最近任务
- 查看 Agent 执行统计

### 数据洞察

路径：`/chat-analysis`

作用：

- 用对话方式查看分析过程和结果摘要

### 报告中心

路径：`/reports`

作用：

- 查看已经生成或保存过的报告
- 下载导出文件
- 彻底删除不需要的报告

现在支持 `彻底删除`：

- 删除历史报告时，会删除历史记录和相关导出产物
- 删除当前会话报告时，会清空当前会话中的报告产物并重置当前会话

### 历史任务

路径：`/history`

作用：

- 查看已保存任务
- 回放历史任务

### 模板库

路径：`/templates`

作用：

- 使用已有模板创建新任务

### 设置

路径：`/settings`

作用：

- 查看系统连接状态
- 查看模型、数据库等配置状态

## 推荐操作顺序

最稳妥的使用顺序如下：

1. 打开 `数据源`
2. 上传文件
3. 点击 `用于新分析`
4. 打开 `输入准备`
5. 填写分析需求并解析
6. 打开 `执行监控`
7. 启动流程并查看图表
8. 打开 `报告交付`
9. 导出结果
10. 需要时到 `报告中心` 下载或删除

## 常见问题

### 为什么需求解析提示先绑定数据源

因为 `输入准备` 页面不负责上传文件，只负责：

- 显示当前已绑定数据源
- 解析分析需求

如果没有在 `数据源` 页面先绑定文件，就不能进入正常分析流程。

### 为什么上传文件立马失败

常见原因：

- 文件超过 `7MB`
- 文件内容解析失败
- 当前文件类型依赖后端解析，但后端服务未正常连接

### 为什么有些图表不能选

因为当前数据中可识别的数值字段不足，无法支撑散点图或雷达图这类多指标图表。

## 当前版本边界

当前项目是单用户 MVP，已经适合本地演示和功能验证，但还不是企业级平台。

当前未包含：

- 登录和权限体系
- 多用户和租户隔离
- 外部数据库连接器管理
- 队列与分布式执行
- WebSocket 实时推送
